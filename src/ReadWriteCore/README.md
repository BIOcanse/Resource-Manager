# ResourceManager.ReadWriteCore

## Current source candidate

ReadWriteCore `0.1.0-dev.85` is the current source candidate. This is a breaking raw-fact interface change. `MetricReadingValue` replaces the former metric display model; field definitions expose stable names, value kinds and raw unit codes. Labels, groups, detail text, meaning descriptions and display values belong to consumers. The capture and projection APIs take no display-copy arguments.

`FieldValue.Integer`, device metric integer values and process metric integer values use `MetricInteger`, an exact signed64/unsigned128 value with raw low/high words. They never pass through double or retain decimal strings. JSON writes lossless decimal strings through `MetricIntegerJsonConverter`; `ReadWriteJsonContext` registers the shared typed reading roots for source-generated serialization. Null remains distinct from valid zero, false and empty bytes.

`HardwareMetricCatalog` retains device and field metadata without sampled values or history. Its `CreateSnapshot()` result is an empty transient carrier for discovery APIs. Cached reads share the original owner current; observation time and sample duration come from the accepted source result. Product and independent package qualification is reported by the consuming project; the source version does not establish publication.

Successful non-catalog captures and subscription collections return a read of the final native public current after publication. Collected dependencies remain independent of public slots. Catalog probes return structural metadata with empty typed values after internal capability discovery; they do not expose a second sampled current. Rejected captures and errors never return an older successful value as a fresh result.

`NativeMetricSnapshotSession.CreateCurrent(in configuration)` creates a publication-only current owner without collector-sized source, rule, plan or persistence arrays. One accepted transaction replaces all requested public dataset slots together, including nullable failures, while unrequested slots remain unchanged. Collection dependencies are independent of the public dataset selection. The typed bank has the declared byte budget; reset and disposal release its current values. Read snapshots are transient raw facts, so consumers compare values and observation identities instead of managed object identity.

## Intel PSys raw platform evidence and accepted publication

The Intel PSys acceptance below was originally qualified with ReadWriteCore/SubscriptionCore `0.1.0-dev.54` / `0.1.0-dev.57`. The interfaces and publication semantics below use the original hardware metric owner and collection borrow.

The two canonical fields are `system_intel_psys_energy_counter_raw` (`unsigned64`, `count`) and `system_intel_psys_energy_unit_joules` (`float64`, `J/count`). They belong to one `intel_platform` target, admitted only for GenuineIntel family 6 model 4E/5E with complete consistent single-package topology and matching current CPUID evidence. The package identity associates this platform locally; it is not a permanent platform serial number. The original Intel reader reads MSR 64D low 32 bits for raw demand and MSR 606 ESU for unit demand independently. Successful zero does not prove BIOS measurement enablement or zero consumption. These are raw register evidence and a nominal unit declaration, not effective joules, interval watts or wall power. Hardware, BIOS validity and OEM domain coverage remain unverified.

Use the existing discovered hardware metric catalog, exact field references and original owner/current/borrow interfaces. Directory failure preserves definitions and clears current values; successful empty or inapplicable topology retires the platform target. Native source completions and values now enter the original accepted publication callback only after the final cancellation check. A rejected publication permit, retired borrow or cancellation before acceptance does not advance native current; prepared control fields are overlaid onto the newly committed native frame rather than restoring an older numeric frame. The original acceptance boundary remains the owner; this adds no owner, cache, resource action or background polling.

GPU `GpuMetrics.AdapterKey` is exact current catalog LUID routing metadata with `JsonIgnore`. It is matched against physical identity and the current catalog before control mapping, including initial discovery with no numeric GPU templates. It is not a new telemetry field or persistent identity, and it adds no JSON wire property.
